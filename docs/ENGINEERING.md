# 工程笔记 · Engineering Notes

> 这是开发过程中的技术记录：液态玻璃的实现细节、踩过的坑、性能取舍、验证方法。
> 面向使用者的说明请看根目录的 [README.md](../README.md)。

---


导入任意音乐 → 自动生成谱面 → 三种玩法可玩。UI 使用 Apple 液态玻璃（真折射 / 色散 / 可换背景 / 可拖动），
**谱面区域刻意不用玻璃**，以保证读谱清晰与帧率。

## 运行

直接双击 `index.html`（Chrome / Edge 最佳）。无需服务器、无需构建、无外部依赖，全部本地运算。

最快体验：打开后点 **「用示例曲立即试玩」**（离线合成 128 BPM 曲目，不用准备文件）。

## 液态玻璃是怎么做的（v0.2 重写）

v0.1 的做法是「自己画一圈亮边再让它扭曲」，结果是一圈发光的硬边加一块发灰的板子 —— 那不像玻璃。
真正的液态玻璃是两个分开的东西：

1. **玻璃本体**：`backdrop-filter: blur() saturate() brightness()` 做磨砂透光。
2. **透镜边缘**：一张**圆角矩形斜面位移图**（canvas 按 SDF 生成）交给 `feDisplacementMap`，
   把背景按边缘法线方向「吸进来」，于是透过玻璃看到的背景在边缘被放大、压缩 —— 这才是折射。

几个必须踩过的坑（都靠截图对比确认）：

- **祖先上一个非 `none` 的 `filter` 会让玻璃彻底失效**（v0.2 最严重的 bug）。
  规范里定义了「backdrop root」：带 `filter` / `backdrop-filter` / `opacity<1` / `mask` / `mix-blend-mode` /
  `isolation:isolate` / `will-change` 指定了上述属性的元素都会成为 backdrop root，
  它**后代的 backdrop-filter 只能采到这个 root 内部的画面**。
  `.screen.is-active{filter:blur(0)}`（一个「等于没写」的写法）就让每块面板的背景变成了空的 ——
  表现就是**玻璃完全透明**，而放在 `.screen` 之外、直接挂在 body 下的设置抽屉却是正常的。
  现在 `.screen` 一律不用 filter，过渡期间 `opacity<1` 也会短暂失效，所以把 opacity 过渡缩短到 0.3s。
- **位移必须向内采样**。向外采样会取到元素外没有 backdrop 数据的地方，边缘出现一圈暗边；
  向内采样既是物理上正确的放大镜行为，又永远取在元素内部。
- **位移量在边缘最大、向内迅速衰减**（`(1-t)^1.6`），才像一块厚玻璃；用正弦形的剖面会在边缘出现重影。
- **色散只做在最外圈**：R / B 通道用「窄斜面」位移图，中心位移为 0，所以中心不串色、不泛白；
  如果三个通道都用同一张图位移，整块玻璃会被邻近颜色染成一片。
- **`.glass` 自己不能有 `filter` / `backdrop-filter`**：那样它会成为 backdrop root，
  子层的 backdrop-filter 就采不到真正的页面背景。所以结构是「.glass 只做框 + .glass__lens 才是玻璃 +
  1.2px 定向边缘光 + 内容层压在最上面」。
- **边缘光必须放在折射层之外**，否则会被位移一起糊掉；`::after` 被边缘光占用后，
  拖动的握把提示改用独立元素 `.drag-grip`，两者才不会互相覆盖。

## 关于「为什么不用光线追踪」

现在这套做法**已经是逐像素折射**：对每个像素，按该点玻璃表面的法线方向去偏移采样背景 ——
这和光追里命中一块平板玻璃后求折射方向、再去找背景是同一套数学，只是把「求交」换成了「查表」。
真正缺的不是折射，而是另外两项，工程量与代价完全不同：

- **高光 / 焦散（specular）**：真玻璃在受光边缘有一条锐利的高光带。现在用 1.2px 定向边缘光近似，
  这是最划算的一笔。
- **折射 DOM 内容**：backdrop-filter 只能采到「背景」，采不到它后面其它 DOM（比如卡片后面的另一张卡片）。
  要做这个必须把页面渲进纹理再上 WebGL 着色器 —— 那是**更贵**而不是更省，而且要接管整页合成。

所以「光线追踪更省性能」这个方向反了：现在的 SVG 位移是单次逐像素偏移，走 GPU 合成；
换成 WebGL 光追需要额外的渲染目标和页面纹理拷贝。真要省性能，该关的是色散（它要跑 3 遍位移）。
设置 → 玻璃质量 的「中」就是保留透镜、去掉色散。

## 背景（可换）

背景的细节量直接决定玻璃好不好看 —— 平滑渐变后面没有东西可折射。
设置 → 背景：6 个预设（深空 / 极光 / 暖霞 / 霓虹 / 石墨 / 影棚）、导入自己的图片、
暗度与模糊滑块。导入的图片会压到 1600px、JPEG 0.72 后存本地；如果平均亮度偏高会自动调高暗度，
避免白字看不清。图片不会上传。`?bg=studio` / `?bg=test` / `?dim=0.4` / `?bgimg=<图片地址>` 可以直接指定；
玻璃参数也能用地址栏直接调：`?bevel=40&scale=90&disp=0.8&lensblur=12&tint=0.15`（都不写进存储）。

## 可拖动的 UI

所有玻璃卡片和顶栏都能拖：抓空白处拖动，落在哪就停在哪，位置按视口比例存本地，换窗口尺寸不会跑丢。
按在按钮 / 滑杆 / 开关 / 拖放区上不会误拖；**单纯点一下不会改变布局**（只有位移超过 5px 才真正开始拖）。
设置 → 数据与布局 可以关掉拖动或一键重置布局。右上角悬停会出现握把提示。

## 自动谱面是怎么生成的

1. **解码**：Web Audio `decodeAudioData` → PCM。
2. **频谱通量**：1024 点 FFT / 512 跳距（约 86 帧每秒），每帧对频点幅度取 `log1p` 后求正向差分。
3. **自适应阈值**：±0.35 s 滑动窗口 `mean + 1.6σ`；峰值拾取 + 85 ms 非极大值抑制 + 抛物线插值细化。
4. **BPM / 相位**：自相关粗估（滞后 0.28–1.05 s，八度归一化到 72–185），
   再用**起音相位锁定值** `|Σ w·e^{i2πt/beat}| / Σw` 在附近细搜精修，幅角同时给出最佳相位，最后吸附到整数 / .5 BPM。
5. **分轨**：六频段能量重心映射到轨道；密集段落切换成楼梯式走向，强拍按概率补和弦。
6. **长按**：起音后持续能量仍高于阈值 42% 时生成，长度受下一颗音符限制。开头留 1.3 秒准备时间。

## 三种玩法

- **下落式**：4 / 6 轨，音符自上而下落到下方判定线。
- **节奏医生式**：单键，7 拍宫格由右向左推进，第 7 拍格高亮。音符会按到下一颗的间距自动缩放，密集段落不会糊成一条。
- **横向**：4 / 6 行，音符由右向左，判定线在左侧。

判定：Perfect ±42 ms · Great ±85 ms · Good ±125 ms · Miss 超过 ±190 ms。时钟取 `getOutputTimestamp()`（已补偿输出延迟），设置里可 ±200 ms 微调。

## 性能取舍

- 玻璃只用在菜单 / 设置 / 结算这些静态界面（同屏最多 4 个透镜面）；**进游戏会加 `body.perf-game`**：
  关掉折射滤镜、暂停背景动画，HUD 换成无模糊的 `glass-lite`。
- 音符用**预渲染贴图**，不用逐帧 `shadowBlur`；粒子池上限 420；`devicePixelRatio` 上限 2。
- 设置 → 玻璃质量：高（透镜 + 色散）/ 中（透镜无色散）/ 低（只有高斯模糊，最省电）。
- 分析长曲需要 2–5 秒（一次性，带进度条）。

测试过程中修掉的真缺陷：

1. **BPM 只精确到整数帧**：128 BPM 被估成 129，0.8% 的误差十几秒后累积到半个节拍网格，对齐节拍时会把音符吸错位置 → 改为相位锁定精修。
2. **12 kHz 以上的 FFT bin 默认归入最低频段**，把分轨用的频谱重心整体拉低 → 改为默认归入最高频段。
3. **一次普通点击就会把卡片变成 `position:fixed`**（只有位移被阈值拦住了），导致布局重排 → 改为位移超过阈值才真正脱离文档流。
4. **节奏医生式密集谱面糊成一条** → 谱面限制到八分音符，渲染按到下一颗的间距自动缩放音符。
5. **玻璃完全透明、设置滑杆全无效果、只有设置抽屉正常** → .screen.is-active{filter:blur(0)} 让 .screen 成了 backdrop root，面板里的玻璃层背景为空；抽屉挂在 body 下所以不受影响（正好解释了「只有那个窗口有作用」）。见 test/root-lab.html。

## v0.4：Phigros 化 + 打击音效 + 多元素谱面

### 玩法界面（贴近 Phigros）

- 音符改成**近白色圆角条**，颜色靠「贴合形状的外发光 + 底部渐变」带出来
  （第一版用径向渐变做发光，宽音符在竖直方向会被贴图边界裁成**方形光晕**，已改为 canvas shadow 贴合形状）。
- 判定线：细亮芯 + 上方柔和光晕，**命中时整条闪一下**。去掉了键位踏板，只在判定线下方留一行很淡的键位提示。
- 命中反馈：**扩散环** + 判定线闪光 + 粒子 + 放大发光的连击数。
- 三种玩法统一这套判定线与反馈。

### 打击音效（`js/sfx.js`）

纯 Web Audio 合成，不依赖任何音频文件：一个极短的宽频瞬态（噪声过带通）+ 一个快速衰减的音高瞬态，
就是音游那种 click。两种音色（干脆 / 明亮），音量独立于音乐，可在设置里开关。
长按尾判完成另有一声轻响。

### 谱面生成：参考人声与多音乐元素

分析阶段每帧多算三样东西（共用一次 FFT，代价很小）：

| 特征 | 用途 |
| --- | --- |
| 三频段能量与**分频段通量**（<220Hz / 220–2200Hz / >2200Hz） | 分别捡起音：底鼓、人声/旋律、踩镲未必会在总包络上形成峰 |
| **谱平坦度**（几何均值/算术均值） | 区分「有音高的乐音」和「噪声」→ 人声 vs 军鼓 |
| **主频**（80–1200Hz 抛物线插值） | 人声/旋律的音高走向 → 生成楼梯式走向 |

起音分类成 `kick / snare / hat / vocal / other`，然后**按层组装**，而不是一视同仁地撒音符：

- **底鼓**踩外轨（0 与末轨交替）——稳定骨架
- **军鼓**踩内轨（1 与倒数第二轨交替）
- **人声/旋律**跟着音高走向走楼梯（这是最像真人写谱的地方）
- **踩镲**交替补在次外轨
- 其它按频谱重心映射；强拍上在底鼓/军鼓处补一条对称和弦
- 后处理：同轨 70ms 内不重复（防连打）、限和弦、开头留 1.3 秒准备

密度滑块主要放大/压缩**次要层**（人声、踩镲），骨架层基本不动 —— 所以调密度是「加花」，
而不是把一首歌的骨架换掉。

> 这里踩了一个很关键的坑：**底鼓在「总包络」上的强度只有噪声类的 0.04 倍**（58Hz 正弦的频谱通量本来就小），
> 统一归一化会让底鼓被强度门槛全部滤掉，谱面只剩镲片。现在每类元素**按自己的频段各自归一化**再取最大，
> 骨架才不会被次要元素淹没。这一个 bug 让「简单」难度的谱面直接变成 0 个音符。

> 第二个坑：分频段强度一开始用「宽带阈值」去减各频段包络，但频段包络是宽带的子集，
> 相减必然为负、被 clamp 成 0，于是所有分频段强度都失效。改成直接取各频段的峰值再按各自最大值归一化。

## v0.4 修掉的两个 bug

1. **主菜单大卡片（英雄卡）玻璃一直不生效**：`.glass__sheen` 用了 `mix-blend-mode: screen`，
   而**子元素一旦有混合模式，父元素就成了 blending root，同时变成 backdrop root**，
   里面的 `.glass__lens` 就采不到网页背景了。模式卡没有 sheen 所以一直正常 —— 这也解释了为什么「只有大卡片坏」。
   验证方法：把 blur 从 0 调到 16，英雄卡内部像素差 **0.00**（失效），模式卡 13.49（正常）；去掉混合模式后英雄卡变成 13.49。
   顺带提醒：`mix-blend-mode` / `filter` / `opacity<1` / `mask` / `contain:paint`，
   以及**动画的 `fill-mode: both`**（会让元素长期处于 opacity 动画状态）都会造成同样的问题。
2. **拖动时其他控件跳动 + 拖动卡顿**：
   - 跳动是因为拖动元素脱离文档流后，兄弟元素用 `margin:auto` 重新居中。现在**开始拖动时把同屏所有卡片一次性固定**（先读完所有 rect 再统一样式），整屏进入自由摆放状态。
   - 卡顿是因为拖动中每帧都要重跑 SVG 折射滤镜（最多 3 遍位移）。现在**拖动期间临时关掉折射滤镜、保留模糊与边缘光**，松手恢复。

## v0.7：谱面生成重写（收尾）

旧版是「起音来了就放音符」，所以会出现三个明显不像人打的问题：**开头就暴走**、**全程不停**、**不贴鼓点**。
v0.7 改成「先看段落结构，再给每小节定预算，最后在小节内挑最重要的起音」。

### 1. 段落结构（解决「开头暴走」）

按小节（4 拍）统计起音能量，做 3 小节平滑后归一化，分成四档：

| 档位 | 能量 | 每小节音符预算（普通难度） |
| --- | --- | --- |
| quiet | < 0.28 | 1 |
| light | < 0.52 | 2 |
| mid | < 0.78 | 3 |
| busy | ≥ 0.78 | 5 |

外加两条硬规则：

- **前两小节若能量 < 0.55 直接不给音符** —— 歌曲前奏通常是舒缓的，不该有音符。
- **连续 3 小节都在打，第 4 小节必须留白**（能量没拉满就整小节空掉，拉满也砍掉大半）。

实测（合成信号：前奏 4 小节只有 pad → 第 5 小节进鼓 → 第 9 小节全开）：

```
easy     18个 0.56音符/秒  最长留白3.74s  留白小节8  每小节: 0 0 0 0 0 2 1 1 0 4 2 3
normal   35个 1.09音符/秒  最长留白2.92s  留白小节5  每小节: 0 0 1 1 1 2 1 1 3 5 4 4
hard     54个 1.69音符/秒  最长留白2.39s  留白小节5  每小节: 0 0 1 2 1 3 2 0 6 6 7 5
expert   72个 2.25音符/秒  最长留白2.39s  留白小节5  每小节: 0 0 2 1 2 4 3 0 7 8 9 7
```

前两小节 0 音符、鼓组进入后逐步加密、副歌爆发、每档都有 2.4~3.7 秒的呼吸。

### 2. 小节内挑音符（解决「不贴鼓点」）

小节里的起音按 `强度 × 乐器权重` 排序，只取预算内的前几名：

```
底鼓 1.00   军鼓 0.95   人声 0.85(困难+) / 0.60   其它 0.60   踩镲 0.35(困难+) / 0.05
```

踩镲权重极低是有意的 —— 16 分踩镲是「全程不停」的主要来源。低难度基本不碰它。

所有音符吸附到 **1/4 或 1/8 拍网格**，并且小节内有最小间隔。

### 3. 起音分类的阈值是实测出来的

原来的判据是 `low > mid*1.12 && low > high*1.1 && 低频峰值拾取器也触发`，
结果**力度小一点的底鼓会被漏成 hat/vocal**，谱面自然不贴鼓点。

用合成鼓组量出真实比值后改成纯比值判据：

| 乐器 | low/(mid+high) 实测 |
| --- | --- |
| 底鼓（58Hz） | **0.82 ~ 1.46** |
| 踩镲 | 0.02 ~ 0.05 |

```
lh > 0.45                      → kick
high > mid*1.25 && high > low*1.5 → hat
tonal > 0.55 && mid > high*0.8    → vocal
mid > low*0.7                     → snare
```

修完后同一段信号：`kick:6 / snare:8 / hat:156 / vocal:24`，与真值（8 底鼓 / 8 军鼓）吻合。

### 4. 节奏医生模式另算

`LR.buildRDPattern` 是独立函数，按 **7 拍乐句** 制谱，每句按该句强度从一组节奏型
（`0,6` / `0,3,6` / `0,2,4,6` …）里挑一个，句内有留白。实测 20/20/27/33 音符（0.83~1.38 音符/秒），
不再是每拍一颗。

### 5. 自动演奏（AUTO）

谱面预览页有「自动演示」按钮，设置里也有「默认自动演奏」开关。
走的是**同一个判定通道**（`_update` 里到点调用 `press()`），所以打出的是真 PERFECT 而不是伪造满分。
实测 80/80 PERFECT、100% 准确率、0 漏、满连击，特效与打击音照常。
## 已知边界

- BPM 估计是自相关 + 相位精修，变速曲 / 自由速度曲仍会偏，谱面可用但对不齐小节。
- 不做人声分离，谱面跟着最强的打击与和声变化走。
- 导出的是 `.json` 谱面（时间 / 轨道 / 长按时长），没有做导入回放。
- 拖动后的卡片宽度按落点时的视口比例固定，极端窗口拉伸下比例可能与原始布局略有差异（重置布局即可恢复）。
